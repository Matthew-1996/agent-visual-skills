# 信息结构 × 视觉风格

先选结构，再选风格。不要用风格掩盖逻辑，也不要把所有内容塞进同一种卡片。

## 结构选择

| 内容关系 | 布局 | 适合 | 避免 |
|---|---|---|---|
| 一个核心连接多项能力 | 中心辐射 | 生态、能力地图、组成关系 | 暗示不存在的流程先后 |
| 明确的先后变化 | 时间轴 | 路线图、阶段、历史 | 同时承载大量横向比较 |
| 从基础到结果逐层成立 | 分层阶梯 | 技术栈、成熟度、保障体系 | 层级没有依赖时硬分层 |
| 两个方案逐项对照 | 二元对比 | before/after、A/B 方案 | 超过两个主方案 |
| 多对象 × 多维度 | 比较矩阵 | 选型、能力覆盖 | 手机端列数超过四列 |
| 从输入收敛到结果 | 漏斗 | 筛选、转化、优先级 | 双向或循环关系 |
| 多个并列重点 | Bento 网格 | 摘要、年度回顾、指标概览 | 每格权重完全相同时失去主旨 |
| 周期或持续反馈 | 环形流程 | 迭代、学习闭环 | 有明确起止的线性流程 |

选择规则：先问读者需要理解的是“组成、顺序、层级、比较还是收敛”。若两种结构都成立，优先选更少箭头、更短阅读路径的一种。

## 克制风格

| 语境 | 风格 | 视觉约束 |
|---|---|---|
| 产品与技术说明 | 编辑式科技 | 中性色底、单一冷色强调、细线 SVG |
| 系统与机制解释 | 技术蓝图 | 网格或坐标感、轮廓优先、少阴影 |
| 高层摘要 | 数据简报 | 大数字、强层级、说明文字短 |
| 公共传播 | 纸张编辑 | 暖白底、深色文字、一个暖色点题 |
| 风险与治理 | 审计档案 | 深底、高对比标签、边界色有语义 |

全图最多一个主强调色和一个风险色；装饰性渐变、发光、纹理只能服务分区。避免霓虹堆叠、伪 3D、过量图标和无意义箭头。

## SVG 与排版

- `viewBox` 与画布比例一致，`svg { width: 100%; height: auto; }`。
- SVG 文字使用与页面相同的中文系统字体；小字号不低于 12px（按 SVG 设计尺寸）。
- 数据比较必须从真实数值编码，不能用夸大的面积或截断比例。
- HTML 卡片负责长文，SVG 负责空间关系；不要在 SVG 中塞段落。
- 页面必须包含一句可独立理解的结论，来源或口径放在不抢焦点的尾注区。
