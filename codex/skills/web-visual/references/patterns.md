# Web Visual 模式

一次只选一个主模式，其他模式只能作为从属区块。首屏应让读者在 10 秒内知道“发生了什么、为什么重要、下一步是什么”。

| 模式 | 首屏结构 | 合理交互 | 适用问题 |
|---|---|---|---|
| Dashboard | 状态结论 + 3–5 指标 + 异常 | 时间范围、指标筛选 | 现在状况如何 |
| Comparison | 决策标准 + 并列方案 + 取舍 | 切换权重、只看差异 | 哪个方案更合适 |
| Timeline | 当前阶段 + 里程碑 + 依赖 | 展开阶段证据 | 进度与阻塞是什么 |
| Explainer | 一句话机制 + 关系图 + 示例 | 逐层展开 | 这个系统如何工作 |
| Report | 执行摘要 + 证据区 + 风险与行动 | 过滤证据、展开注释 | 结论由什么支持 |
| Decision memo | 建议 + 备选 + 判据 + 可逆性 | 情景切换 | 应该做什么决定 |

## 信息层级

1. Verdict：明确结论或状态，不以“概览”代替。
2. Evidence：关键数字、对比或机制图；每块只回答一个问题。
3. Implication：说明证据对目标意味着什么。
4. Action：给出负责人、时点或下一次决策门槛。
5. Footnote：口径、来源、限制和更新时间。

## 原生交互合同

- 控件必须改变可见信息、排序、范围或决策语境；纯动画不是交互价值。
- 控件使用 button、radio 或 disclosure 等原生语义，并提供键盘焦点。
- 初始 HTML 包含核心结论；脚本只增强，不负责从网络加载内容。
- 每个状态有明确文字反馈，不只靠颜色区分。
- 实际点击至少一个关键控件，验证 DOM 状态和可见内容都发生预期变化。

## 响应式合同

- 页面主容器 `width:min(..., 100%)`，网格子项必须可收缩。
- 390px 下控制组允许换行，数字与标签不被裁切，触控目标至少约 40px。
- 避免整页横向滚动；确需宽表时只让表格容器滚动。
- 桌面与手机都用真实浏览器审计：零 console/page error，`scrollWidth <= innerWidth`。
